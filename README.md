# 星铁遗器刷取分析-新手使用指南（v2.9.1）

> 这份文档的目标：**不需要思考，只要把文件放对位置，然后点点点，就能拿到角色的遗器自动分析结果**。
> 想了解原理、参数细节、二次开发，看 [`开发指南.md`](开发指南.md)。
> 本项目基于python开发。将默认各位电脑均包含python运行环境，如果没有的还请麻烦各位自行安装了，这个不难的。

# 快速入门
## 一、本项目能做什么

通过统计所有角色现有装备的遗器的状态，分析接下来体力用在哪个遗器本/哪个角色身上更容易得到提升。

**简单来说/说人话**：本人屯屯鼠，现在又屯了30罐体力，然后我有几队主推队伍（银狼999，异格姬子），还有几队（流萤，大黑塔，遐蝶）还行的队伍。
这些队伍里每个角色的遗器有好有差，但是对我来说我的体力只要能提升这些队伍里的角色那就是有用的。

那么问题就是，哪些角色的遗器可以以最小代价得到提升？又或者说刷哪个副本最容易提升角色遗器的有效词条？

## 二、开始之前，准备三样东西（只做一次）

### 1. 获取角色遗器数据

通过三月七小助手的工具箱可以得到账号的角色遗器数据，相关方法我再看看总结一份教程或者看看有没有现有教程。

### 2. 角色数据放置到项目根目录（`characters.json`）

1. 三月七小助手获取了角色遗器数据之后会在其（三月七小助手）本地产生一个**characters.json**文件。

2. 将这个**characters.json**文件 复制到本项目文件夹里，覆盖掉原来的参考文件。（请勿改名，保持“characters.json”的命名）

### 3. 安装Python 运行环境

首先默认电脑有python，如果没有python

双击 **`00-一键安装依赖.bat`**，它会自动装好需要的两个库。

- 看到 **`装好了，下一步双击 01-一键导出.bat`** = 成功
- 看到 **[错误] 没有找到 python 命令** = 你电脑还没装 Python，去装 [Python 3](https://www.python.org/downloads/)，**安装第一步一定要勾上 `Add python.exe to PATH`**，装完回来再双击 `00`

这一步**只需要做一次**，成功一次后，后续重复使用无需进行。

### 如何看懂分析结果

`分析结果-豆包.xlsx` 共 12 页，内容如下所述。

#### 12 个页签分别是干什么的

这里统一的介绍每个页签的作用，后面**页签查看建议** 有不同目标的使用方法推荐。

| # | 页签 | 使用作用                                               | 查看建议                 |
| --- | --- |----------------------------------------------------|----------------------|
| 11 | **角色部位完成度** | 一行 = 一个角色的一个部位，已按"权重高、部位空"排好序 —— **最上面几行就是现在最该刷的** | ★ 必看                 |
| 12 | **分解建议** | 一行 = 一个套装的一个部位 —— 刚掉的这件留不留、值不值得赌（看后面"升级 / 保底"两列结论） | ○ 建议跳过               |
| 1 | 角色套装优化概率 | 如果去刷某一套装（四件套，两件套），这个角色的这个套装**能得到提升**的概率            | ☆ 提升指定角色时看           |
| 2 | 角色套装部位优化概率 | **角色套装优化概率**的基础上，判断某角色的某个部位得到提升的概率                 | ☆ 提升指定角色时看           |
| 3 | 套装部位优化概率 | 不管是谁，只看"套装 + 部位"，把用这套的所有角色并在一起，算这个部位值不值得刷          | 对照用，参考               |
| 4 | 套装优化准确概率 | 只看"套装"，把用这套的所有角色并在一起，算这个套装值不值得刷                    | 想刷哪个套装时看             |
| 5 | 地点优化概率 | 每个遗器本实际上产出两个套装，所以以遗器本为单位，计算所有使用这个本里套装的角色能得到提升的概率   | （实用）建议用于参考刷哪个本       |
| 10 | 角色权重 | 用于确认加权的各角色权重是多少，如果需要修改请修改“角色权重.xlsx” 。此处仅做权重展示     | 仅用于查看角色权重            |
| 8 | (加权)套装得分 | 前面的套装统计都默认所有角色一样，但实际考虑角色不同强度优先级不一样，所以加权判断套装优先级     | ☆ 考虑实际情况的刷套装时看       |
| 9 | (加权)地点得分 | 同上，按副本排 —— 加权判断刷取地点的优先级 **"体力先砸哪个本"就看这页的排序**       | ★ 考虑实际情况的刷本时看（建议优先看） |
| 6 | (旧)套装优化概率 | 老算法（概率直接相加）留下的对照页，现版本懒得删                           | 无用                   |
| 7 | (旧)地点优化概率 | 老算法（概率直接相加）留下的对照页，现版本懒得删                           | 无用                   |


#### 页签查看建议


先记结论：**真正让你"现在就去做什么"的是第 11 页**；第 1、2 页回答"这个角色该刷什么"；

(加权)地点得分
第 8、9 页回答"整个号先刷哪个本"；其余是数据和对照，看不懂可以直接跳过。

三个容易误会的地方：

- **页签顺序不代表重要性**。第 1~5 页按"角色 → 套装 → 副本"排，第 6、7 页是老算版的留存，第 8~12 页才是加权和结论。
- **"(加权)得分"不是概率**。它乘过权重、又放大了 100 倍，可以超过 100，**只用来比大小排序**，别拿它算"要刷多少次"。
- **第 12 页「分解建议」现在还不太好读**。它按"套装 × 部位"整体算门槛和达标率，适合查数、不适合上手，重做计划记在 `开发指南.md` 的「后续更新方向」里。想省事就用命令行，它只回你一句结论：


#### 其他 

**新手只需要看第 11 页**（下面讲的就是它）；
第 12 页「分解建议」想了解可以去翻，但它现在的输出偏技术向、不好读，**正在重做**。其余页等你看懂再来查开发指南。

#### ① 「角色部位完成度」——决定"刷哪里"

每个角色拆成 6 行（头/手/衣服/鞋子/球/绳子）。已经按 **权重从高到低、同角色内越空越靠前** 排好序：

- **看最上面 10~20 行**：这就是"当前最该砸体力的部位"
- `当前有效词条数` 越少 = 这个部位越空
- `剩余空间(理论)` / `剩余空间(一般)` 正数越大 = 还能加越多条
- `提升概率(1cost)%` = 花 1 cost 定向这一件，强化完能超过现状的概率。**1cost 概率越高的行，性价比越高**

一句话用法：**从上往下刷，刷到 1cost 概率掉到 10% 左右就可以换下一个部位了**。

# 进阶使用

## 四、出问题先看这里

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 双击 bat，**黑窗口一闪就没了** | 没装 Python，或装的时候没勾 `Add to PATH` | 重装 Python 并勾上 PATH；或先双击 `00` 看报什么错 |
| 报 **`PermissionError` / 拒绝访问** | `分析结果-豆包.xlsx` 或中间表正被 Excel / WPS 打开 | **关掉 Excel / WPS**，再双击 `02` |
| 报 **找不到 characters.json** | 文件没放对，或名字不对 | 放到 `01-一键导出.bat` 同目录，文件名必须叫 `characters.json` |
| 分析结果里**少了很多角色** | 这些角色的「有效词条」还没填 / 装备没满级 | 打开 `config\项目配置-豆包.xlsx`，看「有效词条待补」页；或看生成表里「数据不完整」页的原因 |
| 跑完 `01` 之后**配置表多了几行** | 检测到新角色，脚本自动补登了（有效词条留空、权重 1） | 正常行为。给它填上有效词条，再重跑 `01`、`02` |
| 某个角色**明明有却没进表** | 要么有效词条是空的，要么装备凑不齐 | 同上，去看那两页 |
| **角色星级列是空的** | 星级需要人工填，脚本判断不出来 | 配置表「角色有效词条」页第 2 列填 `4` 或 `5`，只影响筛选，不影响任何计算 |

> 修完任何一个问题，都要**重新双击 `01` 再双击 `02`**，光改配置表不会自动生效。

## 五、想让结果更准：三个地方可以填（都可留空）

都在 `config\项目配置-豆包.xlsx`，用 Excel 打开直接改：

| 页签 | 填什么 | 不填会怎样 |
| --- | --- | --- |
| **`角色有效词条`** | 这个角色认哪些副词条算"有效"，顿号分隔，如 `暴击、暴伤、大攻击、速度` | **算不出来**，该角色会被挡在分析之外（这是唯一必须填的） |
| **`角色有效词条`（第 2 列 星级）** | `4` 或 `5` | 可以算，只是没法按星级筛选 |
| `角色权重.xlsx`（另一个文件） | `0.5 / 1 / 1.5 / 2` | 默认按 `1`，等于所有角色同等重要 |

填完记得**重跑 `01`、`02`**。

「角色权重」的意思：你觉得某个角色更重要，就给它 2；不上场的给 0.5。它只影响"多个角色一起看时的排序"，**不会改变任何单件遗器的出货概率**（你练不练这个角色，掉率一模一样）。

## 六、日常怎么用

刷完体力、想再看一遍的时候，只有一件事变了——你的角色数据：

```
重新导出 characters.json
        ↓ 覆盖项目文件夹里那个
双击 01-一键导出.bat
        ↓
双击 02-一键分析.bat
        ↓
打开 分析结果-豆包.xlsx，看「角色部位完成度」最上面几行
```

**不用**每次重装依赖，**不用**每次改配置表（除非你的有效词条判断变了）。

## 八、几个必须提醒的点

1. **这个项目全程离线**。它只读本地 `characters.json`，不向任何服务器发请求、不需要登录、不保存凭证。
2. **数据只在你自己电脑上**。生成的两张 xlsx 都在本地文件夹里。
3. **备份别放项目文件夹里**。项目文件夹会整体传 GitHub，历史产物请放到外面的 `bk\` 目录（见 `文件索引-豆包.md`）。
4. **不要改目录结构**。`code\`、`config\` 和三个 bat 的相对位置是写死在代码里的，挪了会读不到文件。
